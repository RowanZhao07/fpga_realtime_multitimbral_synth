# 延音踏板：工程路径与实现报告

> 本文保留队友 `e9a6c3a` 的历史设计与测试记录。2026-10-22 集成版已经升级为 32 动态声部，同键重按分配新声部；踏板请求接口和包络语义保留，当前差异与实际硬件边界见[协作与更新说明](collaboration_update.md)。

基线：`2d0e549`，本地分支：`feature/sustain-pedal`。本轮聚焦纯 FPGA 输出，暂不选择物理踏板、键盘或光电门方案。

## 1. 工程路径

信号路径：输入适配器 → 统一踏板请求 → 每声部 ADSR → 波表振荡器乘包络 → 13 声部固定增益混音 → 音量/可选回声 → I2S → PCM5102。

选择在包络层延音：声部在松键后保留能量，抬踏板再释音。踏板不直接并入所有音符的 gate，否则会误触发静音声部或丢失同音重按边沿。也不通过循环输出最后一帧音频实现，振荡器和包络继续运行。

实施顺序：先修改包络与声部连接，再加入串口试听入口，最后验证控制边界并导出同一演奏的音频对照。没有新增 CPU、音频采样库或物理引脚。

## 2. 输出规则

| 事件 | 输出行为 |
|---|---|
| 踏板未踩下 | 沿用原来的起音、自然衰减及松键释音 |
| 踩着踏板松键 | 不进入 RELEASE，继续当前起音/衰减/保持段 |
| 抬起踏板，琴键已松开 | 进入原 RELEASE，逐渐消音，避免硬切零 |
| 抬起踏板，琴键仍按住 | 继续发声；电钢琴恢复正常衰减速度 |
| 踏板期间重复按同音 | 从当前包络重新起音，延续活跃声部相位 |
| 空闲时踩踏板 | 不创建音符 |
| 已经进入 RELEASE 再踩踏板 | 不捕获、不恢复这段尾音 |
| 复位或切换测试模式 | 使用已有音频复位路径清除声部 |
| 触摸系统离线 | 禁用延音、清除串口踏板请求，松键声部按原释音结束 |

电钢琴 T1 使用 `floor(level/8192)`（最低为 1）的原衰减步长。踩踏板时用 2 位余数累计，将平均减量降到四分之一，从而将自然衰减时间延长到约四倍。小音量时每四个采样至少递减一次，尾音最终归零，不会因整数除法永久停留。实际包络是分段量化衰减，不是严格连续指数函数；四倍是初始试听设定，可在试听后调整。

T0 正弦、T2 合成弦乐维持原保持电平，踏板释放后释音；T3 金属音保留原有限衰减。踏板状态不修改声部音色锁存、混音增益、波形读表或 I2S 节拍。当前屏幕已有真实声部包络反馈，松键后的蓝色余音会随延音继续显示；实物键灯仍表示物理按键/跟弹，不用来表示踏板状态。

## 3. 接口和操作

- `envelope_adsr`、`synthesis_voice`、`polyphonic_engine` 新增 `sustain_down`。
- `instrument_core.sustain_request`：未来硬件适配器的同步、去抖后电平。高为踩下；与 `clk` 同域。原始光电门或开关不能直接作为此同步接口使用。
- `instrument_core.sustain_active`：实际生效状态，供后续 UI/逻辑使用。
- 现有 `instrument_top` 将外部请求接零，暂无新管脚约束；当前即可利用 UART 试听。
- 串口 `H1` 踩下、`H0` 释放。9600 / 8N1，命令逐条发送并等待 K；H2、H01 等非法值拒绝。
- 外部请求与串口请求取或；H0 仅取消串口请求，不覆盖仍踩住的硬件请求。
- 复位、触摸离线和测试模式清除串口请求。蓝牙链路没有连接状态反馈，不具备自动断连释放功能；保留明确的 H0 操作。

推荐上板试听步骤：发送 T1 → E0 → H0，短按 C/E/G 后松开；发送 H1，重复同样动作，比较松键后的声音；再发送 H0 检查自然释音。保持一个键按下并抬踏板，确认它不被切断；踩踏板重复按同键，确认再次起音；最后发送 H0。

PC 工具示例（COM7 替换为实际数据串口）：

```powershell
python instrument/tools/serial_control.py --port COM7 --command T1 --command E0 --command H1
python instrument/tools/serial_control.py --port COM7 --command H0
```

## 4. 验证设计

新增三项 RTL 仿真：

1. `tb_sustain_envelope`：四种音色松键保持、自然衰减、同音重弹、持键时抬踏板、释音阶段不复活、抬踏板不硬切、尾音归零和复位。
2. `tb_sustain_control`：比特级 UART H1/H0、非法 H2、外部输入与串口合并、触摸离线、模式切换及复位保护。
3. `tb_sustain_audio`：两套真实合成与输出流水线同时演奏相同和弦，一套关闭踏板，另一套开启；导出实际 PCM 并检查削波。

原有测试将新增输入显式置零，继续验证波形、I2S、音色、重按相位、压力、显示和串口。总计 34 项 RTL、8 项串口工具测试，音频分析另行验证尾音强度、最后静音和无新音产生。仿真使用 XSim 2018.3 与 Gowin GW5A 原语模型。

试听素材为 T1、回声关闭、相同原始 PCM 增益。硬件采样率 50 MHz / 1024 = 48828.125 Hz；WAV 头采用最接近的整数 48828 Hz。0.1、0.6、1.1、1.6 秒各弹一组和弦，约 0.1 秒后松键；踏板从 0.08 秒保持到 2.2 秒；3.0 秒附近再次空踩，用于验证不会凭空发声。合成流水线按加速时钟仿真，音频时间由真实采样率还原。

音频数值验证已通过：共同峰值为 7671 PCM（16 位满幅 32767），本示例未削波。第一组和弦松键后的 0.43～0.55 秒窗口，关闭踏板的 RMS 为 0，开启踏板的 RMS 约 1378.22；两路在 2.7 秒后均为精确零，包括后面的空踩窗口。完整回归已完成：34 项 RTL 仿真与 8 项串口工具测试全部通过，音频、和弦、FFT 数值分析通过；八张壁纸共 3,840,000 个 RGB 像素逐像素一致。I2S 检查覆盖四音色 84,207 个双声道帧，内部 PCM 与串行解码结果完全一致。

画面与壁纸两项使用 `xelab --O3 --debug off`，保留全部测试断言；此设置已纳入回归脚本。其余测试沿用原设置。本轮分批完成全部检查，最初中止的画面测试已完整重跑通过。

发现并解决了一项测试环境差异：本机 Conda 的 Pillow 12.0.0 使用 libjpeg 9，重新量化 JPG 时与现有 ROM 不完全一致。用独立目录中的 Pillow 12.0.0 官方 PyPI wheel（libjpeg-turbo 3.1.2）进行原有严格比对后全部通过；另外独立解包 ROM 也验证八张输出与内置数据逐像素相符。未更改图片或 ROM，未放宽断言，未替换系统 Python。依赖文件和 README 已记录可复现的独立环境安装方法。

## 5. 后续扩展与限制

当前是 13 个固定音高声部，不是动态 32 复音。相同音高重弹复用现有声部，不能同时保留多个同音尾音。下一阶段可把 `key_down`、`pedal_down` 和 `release_pending` 纳入动态声部管理，在 note-off 时标记延音声部，pedal-up 时统一进入 RELEASE；分配不足时优先回收低能量尾音，避免直接切断较响声部。

本轮没有半踏板、阻尼器噪声、共振弦模型或踏板后补捕获。可随后加入 0～255 踏板深度以连续控制释音系数，再考虑低成本共振滤波器；这些是未来方案，当前接口只有二值电平。延音保留了声部能量，复音增加时应重新核对混音余量，不能仅根据这段试听无削波就推断所有演奏组合均无削波。

本轮没有新增 RAM 或乘法器算法需求，主要增加踏板状态、包络分支和每声部 2 位衰减余数；具体 LUT/寄存器资源与时序以 Gowin 实际综合布局布线为准。2026-10-17 已改用 E:/Gowin 下的 Gowin 1.9.12.04，修正许可路径和旧 Tcl 选项后，综合、布局布线及现有约束下的时序检查全部通过，已生成延音版本位流。最终逻辑 33707/59904、BSRAM 99/118、DSP 67.5/118；最差建立/保持时间裕量为 0.051/0.187 ns，恢复/移除裕量为 0.107/0.558 ns，最小脉宽裕量为 5.863 ns。建立时间余量较小，参考时钟有 PR1014 普通布线警告，后续扩展应优先检查关键路径和时钟资源。尚未执行实板下载或 PCM5102/音箱试听；原试听文件仍为 RTL 仿真音频。
