## EX3073：sustain_active 输出未连接（1 条）

位置：`src/instrument_top.v:56` 附近的 core 实例。

`sustain_active` 是核心的状态输出。实际延音逻辑在核心内部已经将它接入 `engine.sustain_down`。顶层没有读取这条状态输出，因而提示端口未连接；不是一个缺失的延音控制输入。

若暂时不需要顶层使用此状态，可以在命名端口表显式写：

```verilog
.sustain_active(), // State is consumed inside instrument_core; unused at top.
```

若后续要显示踏板状态，则声明顶层状态线并连接该输出，再接入实际的显示/指示功能。不要把输出接到 0 或 1；常量只能用于合适的输入端口。也没有必要为了这一条警告再添加一个外部引脚。

## EX3791：表达式位宽缩窄（39 条）

Verilog 的右移不会自动把表达式类型变窄，integer 及无位宽常量通常参与 32 位计算。因此，即便只想取某个字节，工具仍会看到“宽表达式赋值给窄目标”。警告不等于已经发生数值溢出。

|---|---|---|
| instrument_screen.v:52 | 104 位包络中取一键的 8 位值 | `display_levels[key_index*8 +: 8]` |
| instrument_screen.v:283 | 取第 8～12 声部包络 | `display_levels[(8+sharp)*8 +: 8]` |
| instrument_screen.v:84 | UART 记录中取一个字节 | `bytes[(7-slot)*8 +: 8]`，slot 必须为 0～7 |
| instrument_screen.v:200 | 文本行中取一个字符 | `label_line[{reverse_col,3'b000} +: 8]`，保留现有有效列判断 |
| font_lut.v:50 | 35 位字模中取一行 5 位像素 | `row<7 ? glyph[34-row*5 -: 5] : 5'd0` |

上述写法直接表达“取这一段”，比先右移整条总线再隐式丢高位清楚。

### 频谱颜色：18 条来自同一类整数插值

位置：`instrument_screen.v:234～240`。t 的实际范围为 0～63，代码用 integer 计算每个 RGB 通道，再写入 8 位字段。

已枚举全部 8 段、每段 64 个小数位置，当前所有颜色通道值均在 73～255 内，8 位足够。建议保持至少原来完整的整数中间运算，在最后通过一个明确的 8 位转换函数取值，并注明范围已验证。

```verilog
function [7:0] colour_byte;
    input integer value;
    begin colour_byte=value[7:0]; end
endfunction
// Example: retain the full multiplication and shift before conversion.
spectrum_colour[23:16]=colour_byte(73+((10*t)>>6));
```

不要简单把所有常量改成 8 位。乘法在右移前需要更宽的中间结果，否则可能先溢出再右移，使渐变颜色真正发生变化。

|---|---|---|
| synthesis_voice.v:57，26→18 | 相邻波表点插值，插值乘积按 8 位小数缩放 | 声明 signed 26 位中间和，明确选择 `[17:0]` 写回；保留 `$signed` 和原舍入项。当前是两点线性插值，正常输入范围可容纳于目标宽度 |
| audio_spectrum.v:60，17→16 | Hann 窗乘积由 Q15 缩放回 16 位 | 保留有符号乘积；在当前非负 Q15 窗范围内，可明确选择 `windowed[30:15]` |

FFT 当前使用 Hann 窗并逐级缩放，先前数值比对通过。但对于这几处，正确目标是保持现有定点精度和动态范围，而不只是让日志安静。若修改位宽/舍入/饱和策略，要补做全幅、极值和频谱数值回归；不要直接将所有存储器改宽，这会明显增加 RAM/DSP 占用。

### TMDS：3 条来自 integer balance 参与运算

位置：`tmds_encoder.v:30、33、36`。disparity 是 signed 6 位，balance 是 integer，导致组合运算升成 32 位再写回 6 位。

按当前转移公式，从复位状态 0 出发，穷举每个可达状态的全部 256 个输入字节，得到可达状态集合：`{-8,-6,-4,-2,0,2,4,6,8}`。全都能放入 signed 6 位（-32～31）。这是数学范围检查，不是重新运行完整 RTL 仿真。

可将 balance 改为 signed 6 位，并将累加用的 ±1、分支中的 0、2 统一为带符号 6 位常量。或者保持 32 位组合中间结果、明确写回 `[5:0]`。无论采用哪种方式，都应保留 TMDS 编解码、控制码和运行差分回归；不要去掉 signed。

## NL0002：13 个 note_frequency 实例被优化（13 条）

每个声部的 KEY 是编译期常量，`note_frequency` 只根据 KEY 输出固定的 32 位相位步长。综合器会把查表函数折叠成常量，移除其模块外壳。对应振荡器、包络和音频声部仍然存在。

这是合理的常量传播优化，可以保留提示。若出于代码组织需要，也可以把常量查表函数写到父模块中，但不能因此期待音质或资源有额外改善。不要为消除此提示给所有实例加 keep 属性。

## PR1014：参考时钟分支使用普通布线（1 条）

信号是 `ref_clk_d`，来自板载 50 MHz 参考输入，供系统与显示的两路 PLL 使用。板级约束将参考输入固定到 V22，显示 PLL 固定到 PLL_R[0]，三个输出时钟也有 CLOCK_LOC 约束。该警告表示工具在参考时钟连接的某一段采用普通布线，可能带来额外延迟或偏斜；不能仅凭这句话判定 V22 管脚错误。

当前最新报告的 PRIMARY 和 LW 资源均为 8/8。PRIMARY 除参考、系统、像素和串行时钟外，还包含 monitor_ce 和 core/engine/pipeline[0/4/5] 等使能信号。资源使用情况说明值得进一步检查全局网络分配，但还不足以证明资源占满就是该警告的唯一原因。

具体排查步骤：

1. 在 IDE 的布局/时钟资源视图中追踪 V22→两路 PLL 的 CLKIN，定位究竟哪一段使用普通路由。
2. 对照芯片和板卡的时钟连接，检查固定 PLL 位置与输入专用时钟通路是否匹配；先评估内部 PLL 放置和网络分配，保留板载晶振的实际管脚。
3. 检查 monitor_ce 和 pipeline 使能是否适合继续占用 PRIMARY 资源；必要时评估局部布线或复制局部使能寄存器，减少全局资源竞争。
4. 每次调整后，在官方 IDE 重新布局布线，并核对 setup、hold、recovery、removal 和最小脉宽；随后验证 PLL 锁定、HDMI 和音频长时间稳定性。

不能通过添加不真实的 false_path、删除时钟约束、随意改晶振管脚来消除此警告。当前时序报告通过，可以继续基础上板调试，同时保留这个时钟路由注意项。

## 建议处理顺序

- 当前调试：以最新成功完成记录和时序报告为准，先完成触摸、延音和显示实板检查。
- 第一轮源码清理：显式处理 unused 输出、字节/字模/包络位选、计数器和坐标宽度，保持结果等价。
- 第二轮数值与结构检查：对 FFT 和 TMDS 完成范围/符号确认，再清理其位宽提示；对 PR1014 单独检查时钟结构和布局。

后续若实际修改 RTL，应在官方软件重新编译，并复查相关仿真与时序。清理 warning 与修复功能错误是两种不同工作，最终判断应依据计算范围、测试结果和时序报告。
