# 触摸输入 + 默认延音：基础烧录调试版

适用情况：保留项目原有的触摸输入和音频接线，暂时没有延音踏板。不需要增加踏板、光电门或新的 FPGA 引脚。音符由实际触摸触发。

## 默认行为

| 项目 | 调试版默认值 |
|---|---|
| 音色 | T1 电钢琴 |
| 延音 | 触摸系统上线后默认开启 |
| 主音量 | 2048/4096，即 50% |
| 回声 | 关闭 |
| 自动演奏 | 无 |
| 压力输入 | 有传感器时沿用压力控制；离线时沿用主音量 |
| 触摸离线 | 禁用有效延音、释放按键，保留原离线保护 |
| 复位/重新上线/退出校准模式 | 恢复调试版默认延音开启 |

电钢琴松键后仍按约四倍自然衰减时间逐渐变小，最终消音。同音重按会重新起音，当前每音高复用一个声部。正弦和弦乐切换后可以长时间保持；需要通过 H0 释放延音，或重新下载/复位回到电钢琴默认状态。

## 用高云 IDE 编译和烧录

直接在高云官方 IDE 打开 `instrument/instrument_touch_debug.gprj`。器件为 GW5AT-LV60PG484AC1/I0，顶层为 instrument_top。执行综合及布局布线，由你在 IDE 中生成 `instrument/impl/pnr/instrument_touch_debug.fs`，再用 Gowin Programmer 的 GW5AT-60B → SRAM Program 下载。断电后 SRAM 配置失效。

详见项目内的 [高云 IDE 打开说明](../instrument/OPEN_IN_GOWIN.md)。Include Path 为 src、VCCX 为 1.8V、Use CPU as GPIO 开启；首次从 GitHub 下载或清理后，建立 impl 目录并将 config/touch_debug_process_config.json 复制为 impl/instrument_touch_debug_process_config.json，再打开工程。

两种工程使用同一套核心源码、管脚和时钟约束。调试工程通过 config/touch_debug_top.vh 设置顶层调试参数，保持原有层级路径；正常版入口 instrument/instrument.gprj 仍默认关闭延音。

## 烧录后检查

1. 接原触摸板，确认正常上线；若连接 HDMI，右上角及状态区域应显示 `SUST DEBUG`，底部显示默认延音及 H0/H1 提示。`TOUCH OFFLINE`/`ADC OFF` 等在线标记继续反映真实外设状态。
2. 短触 C4 后松开。物理按键状态恢复，声音继续逐渐变小；屏幕余音、包络条和 PCM 波形随声音变化。
3. 连续短触 C4、E4、G4，观察尾音叠加；再次触 C4，检查能重新起音。
4. C0 继续用于原音色/回声控制，C1/C2 继续调音量，其他原有触摸功能保持。
5. 若已有蓝牙或数据 UART，可发送 H0（逐条 LF/CRLF，等待 K），检查已松开的音进入释音；发送 H1 后再次演奏。串口是可选调试入口，默认延音不需要发送任何命令。
6. 触摸掉线时有效延音关闭、音符按原释音结束；重新上线后自动恢复延音默认开启。H0 的关闭设置不跨掉线、模式切换或复位保存。

## 实现与验证

核心新增默认延音、默认音色参数；普通参数默认值保持原行为。调试参数不把 sustain_request 固定拉高，因而 H0 仍可取消串口踏板状态。实际延音仍受触摸在线状态和校准模式约束。

新增 `tb_touch_debug`，用真实 touched→performance_control→声部路径检查触摸起音、松键延音、普通默认关闭、H0/H1、掉线/复位恢复及 C0 音色切换，并检查调试显示标签。该测试加速采样使能以缩短仿真时间；不把此测试视为实板音频采集或 I2S 电气测试。
