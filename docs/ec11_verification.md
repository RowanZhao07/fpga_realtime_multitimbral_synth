# EC11 16 档延音验证记录

日期：2026-10-24。基线为 `origin/main` 的 `e37c4e8`，包含 32 动态声部及自动音区 GUIDE。本轮只交付源码、工程与说明，不生成位流或执行烧录。

## 实现范围与理由

由 chenxi639 主导，Codex 协助实现和验证。现有输入改为标准五脚 EC11：旋转选择 01～16 档尾音速度，按压切换延音状态。保留三种独立官方 IDE 入口，避免默认开启的旧触摸调试配置掩盖新旋钮开关。

32 个包络各自保存两个 5 位衰减计数器和尾音资格标志。档位 N 使延音期间每 N+1 个采样执行一次原减量；无需新增包络乘法器或可变除法器，音频调度状态数保持不变。关闭后不硬清零；已经普通释音的声部不会因后来开启延音而复活。

新增五项及旧功能相关八项共 **13 项 RTL 测试全部通过**。旧功能集合为 tb_sustain_envelope、tb_sustain_control、tb_voice_allocator、tb_touch_debug、tb_top_integration、tb_screen_feedback、tb_guide_timing、tb_guide_auto。完整回归入口现在包含 46 项测试；本轮验证上述相关集合，不声称已重新运行全部 46 项。

使用 XSim 2018.3 与 Gowin GW5A 原语模型。输入/核心测试缩短了去抖计数和 UART 位周期；完整顶层测试加速了波形分析采样与场消隐，仅用于验证连接、数据发布及显示。32 声部调度另用真实引擎负载测试，其最大计数为 829 拍，低于每采样 1024 拍预算。上述加速测试不能用来声称测得了整机触键到音频延迟。

可用 `instrument/sim/run.ps1 -Only tb_ec11_sustain,tb_variable_sustain,tb_ec11_core,tb_ec11_allocator,tb_ec11_top -NoAnalysis` 重跑新功能集合；按本机安装情况指定 VivadoBin、GowinSimLib 和 Python。回归脚本现使用相对源文件名，避免新增测试后触发 Windows 批处理启动器的命令行长度限制。

## Gowin 综合

在独立临时工程中使用 Gowin 1.9.12.04 执行 `run syn`，综合成功。综合前后源文件哈希与项目当前源码核对一致。本次没有运行布局布线；验证目录内没有生成 `.fs`。

综合资源 XML 的汇总为 Register 7124、LUT 25832、ALU 2762、BSRAM 29、MULTALU27X18 15、MULT12X12 33。旋钮控制器自身为 Register 61、LUT 40、ALU 42，无 DSP。各声部包络也没有 DSP。这些是综合阶段的原始资源分类，不能与布局布线报告的 Logic、CLS 或等效 DSP 数直接比较。

综合仍有 64 条警告：EX3073 两条、EX3791 48 条、NL0002 14 条；未做整库告警清理。两条未连接输出为顶层未单独使用的 sustain_active（实际状态已通过 sustain_info 使用）及压力驱动未消费的 error_code；NL0002 包含常量音高与内置曲谱的优化。位宽截断警告需结合具体表达式持续审查，不能用综合成功代替数值与边界测试。

**本轮没有布局布线时序结果。** 最新主分支此前的 setup 余量较小，不能把旧报告当作 EC11 新版的时序保证。烧录前必须由官方 IDE 完成布局布线，检查 setup/hold、recovery/removal、最小脉宽和输入同步路径；不放宽现有时钟约束。
