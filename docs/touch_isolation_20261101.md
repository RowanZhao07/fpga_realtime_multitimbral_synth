# 触摸链路：诊断版正常、演奏版掉线的对照排查

## 已确认的事实

用户反馈：相同接线下 `instrument_wiring_debug.fs` 的三条外设链路正常，触摸琴键时键灯也能响应；新旧演奏版在完全不触摸时，A/B 在线位仍反复变化，F 失败计数持续增加。

已将本机 `.fs` 哈希与 2026-10-31 构建记录核对：诊断版为 `6afad0da…cd732`，EXPR L1 为 `da65392c…29a4`。两版发布时的 `mpr121_controller.v`、`i2c_register_master.v`、`board_clock.v`、`hc595_driver.v` 相同；触摸引脚、驱动强度、上拉模式也相同。不是已发现了两版触摸地址或球位配置不同。

诊断版把 `instrument_core` 的时序逻辑保持在复位，但 `performance_control.gates` 和 `key_lights` 是触摸状态驱动的组合输出，独立的 74HC595 驱动仍运行。**因此，诊断版能正常亮键灯，与音频核心被复位并不矛盾。** 先前将“核心复位”理解成“键灯也不响应”不准确。

演奏版即使没有按键、输出零音频，也持续产生约 3.125 MHz BCK 和 48.828 kHz LRCK，并执行音频/频谱处理。既有时序报告通过建立、保持和脉宽检查；这并不测量实物供电、电平或线间串扰。

引脚报告还确认：两组触摸和 I²S 输出位于 Bank 1，ADC 位于 Bank 2。因此，ADC 正常不能排除 Bank 1 的活动相关问题；这只是待验证方向，尚无供电或串扰的实测结论。

**具体硬件根因尚未确认。** 以下文件是为了取得能区分原因的实板证据，不是已验证的修复版。

本次同一文件、同一布局布线的测试中，**触摸 A 的故障只出现在外部 I²S 开启的三个窗口**；关闭输出后恢复，触摸 B 七个窗口均未记录失败或离线。关闭键灯未改善，内部核心和 FFT/波形分别运行时也没有复现。`R001` 未记录额外系统复位。顶部 `ADC1` 只反映拍照时在线，不能据此宣称 ADC 在全程无瞬时故障。

由此优先定位到 **I²S 输出活动及其外部线路/负载对触摸 A 链路的影响**，不再把 FFT 算法或键灯驱动当作首要方向。E1 表示该窗口最后一次失败是 NACK，意为控制器未采到有效应答；它不区分是哪个字节，也不能单凭它判定 MPR121 损坏。F040 是窗口内 40 次失败事件，并非 40 个毛刺；现有 0.5 秒重试等待会限制计数增长速度。

尚未区分的机制包括线间耦合、接触/焊接异常、局部电源或回流扰动、I/O 输出边沿/负载影响。该结果并没有直接测量电源或串扰波形，也没有证明所有软件/时序问题都已排除。

用户进一步确认：FPGA J13 与 PCB U1 之间使用单根可拔杜邦线。当前约束及保存 PCB 网表已复核：触摸 A 为 `E14/J13-1 → U1-1`（SCL）、`E13/J13-2 → U1-2`（SDA）；音频为 `C15/J13-3 → U1-3`（BCK）、`C14/J13-4 → U1-4`（LRCK）、`B13/J13-5 → U1-5`（DIN）。它们在连接器上相邻，但网表本身不能证明实际飞线或 PCB 铜线之间存在串扰。

下一步仅改变飞线的摆放位置：全部断电后，把触摸 A 两根杜邦线与三根音频线分开走，避免长距离并排、贴靠或缠绕；有空间时拉开数厘米。保持两端针位、线材、电源和其他连接不变，不需要拆焊。重新加载同一个 `instrument_touch_isolation.fs`，保持不触摸，等 154 秒到 DONE 后返回完整屏幕照片。

若 2/4/5 行失败数明显减少或归零，支持布线位置/接触状态相关的干扰方向；单次改善仍需复测。若仍接近 40/40/39，则此项调整未解决，不能据此否定 PCB 内部、DAC 负载或公共回流等路径。此次尚未更改演奏固件，也未宣称故障已修复。

用户明确确认：只把触摸 A 两根线与音频三根线分开摆放，针位、供电及其他连接未改，测试全程未碰琴键。第二张照片同为 `TOUCH ISOLATION T1 / DONE / DATA FROZEN`；顶部 `A1 B1 ADC1 R001`，最终模式 6，`FFT 18 FR 97 SCOPE 7E`。原图和转录记录保存为 `.local/touch-isolation-20261101/hardware-run-02.*`。

|---|---|---|---|
| 0 BASE | F000 E0 U1 D0 | F000 E0 U1 D0 | F000 E0 U1 D0 |
| 1 CORE | F000 E0 U1 D0 | F000 E0 U1 D0 | F000 E0 U1 D0 |
| 2 I2S | F040 E1 U1 D1 | F005 E6 U1 D1 | F000 E0 U1 D0 |
| 3 FFT/SCOPE | F000 E0 U1 D0 | F000 E0 U1 D0 | F000 E0 U1 D0 |
| 4 NO LED | F040 E1 U1 D1 | F003 E6 U1 D1 | F000 E0 U1 D0 |
| 5 FULL | F039 E1 U1 D1 | F007 E6 U1 D1 | F000 E0 U1 D0 |
| 6 BASE | F000 E0 U1 D0 | F000 E0 U1 D0 | F000 E0 U1 D0 |

相同统计窗口的 A 失败事件总数从 119 降到 15，观察到约 87% 的减少；这是两次运行的计数比较，不是统计置信度或线路误码率。故障仍仅出现在外部 I²S 开启阶段，支持飞线位置/连接状态相关的干扰方向，但尚未修复，也未唯一确定耦合位置或电源路径。

**E6 的准确边界：** `mpr121_controller.v` 在状态轮询完成、I²C master 未报告传输失败且 `result[15]=1` 时记录 E6。首字节放 `result[7:0]`，因此该位对应寄存器 `0x01` 的 bit 7。NXP MPR121 数据手册 §5.2 将它定义为 OVCF：检测到 REXT 引脚过流；真实置位时芯片进入 Stop Mode，ECR 低六位和其他状态/输出数据会清零。它不是对整块 PCB 的 5V 电源电流测量。当前逻辑遇到该位后立即进入重初始化流程，没有保存故障时的第二次状态读数或 ECR，因此不能区分真实 OVCF 与受干扰的读回数据。E 是窗口最后一次错误，不代表窗口内所有失败类型均相同。

下一次只做 **BCK 外部连接隔离**：先全部断电，在 FPGA 端拔下 `C15/J13-3 → PCB U1-3` 这一根 BCK 杜邦线；PCB 端保留，悬空插头固定好避免碰到其他针。保留 `C14/J13-4`（LRCK）、`B13/J13-5`（DIN）、触摸线、5V 和 GND，维持本次分开走线的摆放。重新运行同一个隔离文件至 DONE；这是短时间静音诊断，不能作为正常演奏接法。测试后需要断电才能恢复原 BCK 接线。

若 2/4/5 行归零，支持剩余问题依赖外部 BCK 线路或其所驱动的 DAC 工作状态；仍不能仅据此区分串扰、负载和 DAC 活动导致的电源变化。若错误仍在，说明 BCK 单线隔离不足，后续再区分 LRCK/DIN、PCB 内部及共同回流路径。本次没有修改/屏蔽 E6 检查，也没有生成新的演奏固件。

依据：[MPR121 数据手册 §5.2，第 11 页](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)。

本次在 I2S/NO LED/FULL 阶段，FPGA 内部和未接线的 C15 输出仍按程序工作，LRCK/DIN 外部连接也保留。因而结果进一步将依赖关系缩小到 **BCK 外部线路/负载及随 BCK 恢复活动的 DAC**，而不是简单关闭全部内部合成/FFT 后不报错。尚不能唯一确定是线间耦合、接触/焊接、公共回流、电源变化还是输出端负载相关的电气问题；断线后失去正常音频，所以这不是正常演奏条件下的验收通过。

下一步恢复音频连接并改善飞线回流：全部断电后，恢复 `C15/J13-3 → PCB U1-3`，让这根 BCK 线与现有 `GND/J13-12 → PCB U1-12` 地线贴近成对走线，可用两根完整绝缘的线轻轻绞合。两根线仍分别连接各自针脚，不能把 BCK 与 GND 电气短接。保持这对线远离 E14/E13 两根触摸总线及触摸电极引线；其他连接、固件和线材先不变。此项是基于现有对照结果的低改动尝试，不保证解决所有 PCB 内部或 DAC 活动相关因素。

原理参考：NXP I2C 手册 §7.5 说明信号与回流线配对的抗干扰意义；TI PCM510xA 手册 §12.1 强调数字时钟回流、布局隔离及近端去耦。BCK/GND 飞线配对是本项目的工程验证建议，并非这些手册对当前实物根因的结论。

## BCK 迁移到 D16 的独立版本

用户提出 FPGA 原区域引脚可能存在问题，希望迁移到 D16/E16 等空闲脚再试。此次只迁移已被对照锁定的 BCK，暂不迁移其他信号。Sipeed NEO Dock-60K Rev1.4 原理图第 19 页确认 `J13-27=SDRAM0_WE`、`J13-28=SDRAM0_A4`，官方 `sdram_neo/src/sdram.cst` 分别映射到 D16、E16，并使用 LVCMOS33/3.3V；原工程未占用这两个球位。

| 信号 | 原 FPGA 端 | D16 版 FPGA 端 | PCB 端 |
|---|---|---|---|
| BCK | C15 / J13-3 | **D16 / J13-27** | **仍是 U1-3 → P4-2** |
| LRCK | C14 / J13-4 | 不变 | U1-4 → P4-4 |
| DIN | B13 / J13-5 | 不变 | U1-5 → P4-3 |

E16/J13-28 保留不用。不要把 PCB 端随 FPGA 端一同移到 U1-27；新连接是跨针号的 `FPGA J13-27 → PCB U1-3`。D16 版中 C15 不再承担 BCK，原 FPGA J13-3 留空。

配套文件：

- `dist/instrument_touch_isolation_bck_d16.fs`：仍是七阶段 T1 诊断，屏幕标题与 C15 版相同，需按下载文件名区分。
- `dist/instrument_expression_bck_d16.fs`：完整 EXPR L1 演奏功能，屏幕标题与原演奏版相同。

断电改线后，先下载 D16 诊断文件，保持不触摸约 154 秒；七行 A/B 应全部 `F000 E0 U1 D0`。若通过，再下载 D16 演奏文件，静置一分钟并演奏至少五分钟，检查声音、触摸和键灯。若仍报错，返回诊断截图；仅迁移改善也不能证明 C15 芯片内部损坏，因为同时改变了引脚、开发板线路、飞线位置与 FPGA 布局布线。

工程仅改变 `IO_LOC "dac_bck" C15;` 为 `IO_LOC "dac_bck" D16;`，音频时序、引脚电气属性和全部 RTL 保持原样。新工程使用 `config/instrument_bck_d16.cst`，原 `src/instrument.cst` 及既有下载文件保留。构建脚本拒绝 D16 约束除这一行外出现其他差异，避免复制的约束长期失配。

复现命令（在仓库根目录，工具路径沿用现有配置或传 `-GowinShell`）：

```powershell
./instrument/build.ps1 -TouchIsolation -BckD16
./instrument/build.ps1 -Expression -BckD16
```

D16 的构建/引脚/时序证据保存到 `.local/bck-d16-20261101/`；实板验证尚未完成。下载原 C15 文件时，需要断电后将 FPGA 端恢复 C15/J13-3，否则原文件无法经 D16 提供 BCK。

[TI PCM510xA 数据手册 §11.5.2](https://www.ti.com/lit/ds/symlink/pcm5102a.pdf) 说明异常/停止的音频时钟会使 DAC 进入待机，正确时钟恢复后会自动开始上电序列。因此不能将断过 BCK 后的持续静音直接认定为需要专门软件解锁；应先核实正确时钟和音频数据实际抵达模块。

下一步保持当前文件和接线，万用表使用直流电压档（手动量程选 20V），黑笔固定在 PCM5102 模块 GND，依次记录模块端 `VIN / BCK / LRCK(LCK)` 电压。保存设计中它们对应 P4-6/P4-2/P4-4，GND 为 P4-5；以模块可辨认的标记确认后测量，不猜排针方向。

现有带稳压模块的 VIN 预期接近 5V。3.3V、约 50% 占空比的 BCK/LRCK，直流档通常只能看到接近半电源的平均电压；约 1.65V 不能证明 3.125MHz/48.828kHz 的频率、边沿或时序正确，仪表响应也会影响结果。若模块端读数异常，再对比 FPGA/PCB 两端；不在带电状态用通断或电阻档。

如电源/时钟初筛未发现问题，后续检查 XSMT（低电平静音）、FMT（本工程需 I2S 配置）、SCK 接地、DIN 线路，以及 AUX/音响输入。TI 手册说明时钟错误会使 PCM510xA 静音/待机，恢复有效时钟后会自动启动，不能仅凭之前拔过 BCK 就认定其永久锁死。依据：[TI PCM510xA 手册 §9.3.5.3、§11.2、§11.5](https://www.ti.com/lit/ds/symlink/pcm5102a.pdf)。本次尚无上述电压实测值，不修改 RTL 或 DAC 焊接跳线。

各阶段始终使用同一份布局布线、同一套 I²C 驱动、相同触摸初始化和轮询速率。阶段切换不重置触摸控制器，不清除其故障历史；逐阶段统计由独立失败事件驱动，不会被旧诊断 F=255 饱和挡住。失败事件涵盖原控制器的总线失败、配置回读不匹配和 OVCF。

每行分别显示 TOUCH A/B 的 `Fxxx Ex Ux Dx`：

- **F**：该阶段 20 秒统计窗口内新发生的失败次数；255 表示至少 255 次。
- **E**：该窗口最后一次失败类型；E0=未记录失败，E1=NACK，E2=SCL 超时，E3=SDA 卡低/总线恢复，E4=其他超时，E5=配置回读不匹配，E6=MPR121 过流状态位。
- **U1**：该窗口内至少一次处于在线状态。
- **D1**：该窗口内至少一次处于离线状态。`F000 U0 D1` 仍不是健康状态，可能一直在等待恢复。
- 顶部 **R**：配置以来观察到的系统复位次数，含正常启动；通常为 001。重新下载会重新计数，运行中复位会使七阶段重新开始。
- **FFT / FR / SCOPE**：处理结果校验字节与 FFT 完成帧计数（十六进制、回绕）。这些用于保留并观察真实运算路径；校验值为零本身不代表处理停止。

测量结束后逐阶段结果冻结；顶部在线位和处理观察值仍是实时状态。表格中的 F 不是演奏版从开机起累计的 F。

## 如何解释对照结果

|---|---|
| 0 BASE 稳定，1 CORE 出错 | 内部运行负载、供电/时钟、实现相关因素；外部 I²S 此时未输出 |
| 1 CORE 稳定，2 I2S 明显出错 | 音频时钟/数据输出及其负载；检查 I²S 与触摸线的邻近关系、回流路径、DAC 对电源的影响 |
| 1 CORE 稳定，3 FFT/SCOPE 出错 | 频谱/波形处理活动相关的负载或实现问题；不能简单解释成处理器“抢占”了触摸通信 |
| 4 NO LED 稳定，5 FULL 出错 | 键灯驱动活动相关问题，包括时钟干扰、接线串接或供电影响 |

界限：这份对照使用完整表情引擎和三通道 ADC。原独立诊断版仅扫描压力/X 两通道，且静态复位会让综合器删去不少逻辑。新 BASE 是运行时静默对照，不与原诊断文件逐位等同；新界面也改变了显示逻辑和最终布局。对照可缩小相关路径，但不能单凭照片在“串扰”和“供电变化”之间作最终定论。

CORE 阶段还运行核心控制和开发板状态 LED 等逻辑，因此该阶段出错不能直接细化为某一个乘法器或 FFT 算法的问题。

若需测量电源，必须在模块自己的 VCC/GND 上测量。万用表的平均电压不能排除纳秒/微秒级毛刺。当前阶段不要求重新焊接或替换模块。
